# Inline purchase edit and delete — Design Spec

Date: 2026-09-17  
Status: Approved for user review  
Version: v1

แก้กฎใน `2026-09-09-purchase-first-warehouse-design.md` ที่เคยห้ามแก้หรือลบประวัติซื้อ

## Problem

กรอกราคาหรือปริมาณผิดตอนซื้อเข้าแล้วแก้ในตารางไม่ได้ ต้องมีทางแก้ในแถวและลบรอบที่ผิด โดยคงเหลือกับต้นทุนเฉลี่ยต้องถูกต้อง

## Goals

- ตารางประวัติซื้อมีปุ่ม **แก้ไข** และ **ลบ** ในแต่ละแถว
- แก้ในแถวได้: วันที่ซื้อ, ปริมาณ, ราคาเต็ม, เงินที่จ่าย
- ส่วนลดในแถวคิดใหม่อัตโนมัติ = ราคาเต็ม − เงินที่จ่าย
- ลบได้ทั้งรอบ ถามก่อนลบ
- คงเหลือ ต้นทุนเฉลี่ย และแพ็กล่าสุดคำนวณใหม่ใน transaction เดียว
- ถ้าลบหรือลดปริมาณแล้วคงเหลือจะ < 0 ห้ามทำ บอกเป็นภาษาไทย

## Non-goals

- ไม่แก้ชื่อวัตถุดิบหรือแหล่งซื้อในแถว
- ไม่แก้หรือลบประวัติขายออก
- ไม่ลบวัตถุดิบทิ้งแม้ลบรอบซื้อสุดท้าย (คลังยังมีชื่อ คงเหลือ 0)
- ไม่เปลี่ยนสูตรเฉลี่ยต้นทุน (ยังเป็นค่าเฉลี่ยถ่วงน้ำหนักเท่ากันของเงินที่จ่าย ÷ ปริมาณ)
- ไม่มีประวัติการแก้ (ไม่เก็บว่าใครแก้เมื่อไร)

## UI

หน้า `/purchases` ตารางเดิม เพิ่มคอลัมน์ปุ่มท้ายแถว: แก้ไข, ลบ

กดแก้ไข: แถวนั้นเป็นช่องกรอกของวันที่ ปริมาณ ราคาเต็ม เงินที่จ่าย ส่วนลดอ่านอย่างเดียว ปุ่มในแถวเป็น บันทึก กับ ยกเลิก แก้ได้ทีละแถว

กดลบ: ถามว่าต้องการลบรอบนี้หรือไม่ ถ้ายืนยันค่อยเรียก RPC

อยู่หน้าซื้อเข้าหลังสำเร็จ รีเฟรชตาราง

## Calculation

ก่อนแก้หรือลบ ให้

```
sold = (ผลรวมปริมาณทุก stock_purchases ของวัตถุดิบนี้) - remaining_quantity
```

หลังได้รายการซื้อชุดใหม่ (แก้ค่าในรอบนั้น หรือตัดรอบที่ลบออก):

```
new_remaining = (ผลรวมปริมาณชุดใหม่) - sold
```

ถ้า `new_remaining < 0` ทั้งรายการล้มเหลว ไม่เขียนอะไร

ถ้าผ่าน เรียงรอบที่เหลือตาม `purchased_at`, `created_at`, `id` แล้ว

- `remaining_after` ของแต่ละรอบ = ผลรวมปริมาณตั้งแต่วงแรกถึงรอบนั้น
- `unit_cost_after` ของแต่ละรอบ = ค่าเฉลี่ย `(amount_paid / quantity)` ของรอบตั้งแต่แรกถึงรอบนั้น
- `ingredients.remaining_quantity` = `new_remaining`
- แพ็ก: ถ้ายังมีรอบ เซ็ต `purchase_quantity` / `purchase_price` เป็นปริมาณและเงินที่จ่ายของรอบล่าสุดในลำดับด้านบน ถ้าไม่มีรอบเหลือ ไม่ทับแพ็ก คงเหลือเป็น 0

ตัวอย่าง: ซื้อ 100 จ่าย 400 แล้วซื้อ 100 จ่าย 450 คงเหลือ 200 เฉลี่ย 4.25  
แก้รอบสองเป็นจ่าย 500 → เฉลี่ย (4 + 5) / 2 = 4.50 คงเหลือยัง 200  
ถ้าขายไป 150 เหลือ 50 แล้วจะลบรอบ 100 กรัมรอบแรก → `new_remaining` จะเป็น 50 − 100 = -50 ห้ามลบ

## Atomic RPC

ไฟล์ใหม่เท่านั้น ห้ามแก้ migration ที่รันไปแล้ว

`update_stock_purchase(p_id uuid, p_purchased_at date, p_quantity numeric, p_amount_paid numeric, p_list_price numeric)`  
คืน jsonb `{ ok: true }` หรือ `{ ok: false, reason: "shortage" }`

`delete_stock_purchase(p_id uuid)`  
คืนรูปแบบเดียวกัน

ตรวจ: ปริมาณ ราคาเต็ม เงินที่จ่าย > 0 และเงินที่จ่าย ≤ ราคาเต็ม และมีวันที่ซื้อ (ฝั่งอัปเดต)

ล็อกแถววัตถุดิบด้วย `for update`

## Error handling

| กรณี | ข้อความ |
|---|---|
| ช่องแก้ไม่ผ่านกฎเงิน/ปริมาณ/วันที่ | เหมือนฟอร์มซื้อเข้า |
| คงเหลือจะไม่พอตอนลบ | `ลบไม่ได้ คงเหลือจะไม่พอ` |
| คงเหลือจะไม่พอตอนแก้ | `แก้ไม่ได้ คงเหลือจะไม่พอ` |
| RPC หรือเครือข่ายล้ม | `บันทึกไม่สำเร็จ` / `ลบไม่สำเร็จ` |
| ไม่ยืนยันลบ | ไม่ลบ |

## Testing

1. ซื้อสองรอบ 100/400 และ 100/450 แก้รอบสองเป็นจ่าย 500 → เฉลี่ยแสดง 4.50 คงเหลือเท่าเดิม
2. ขายจนเหลือ 50 ลบรอบ 100 ไม่ได้ ข้อความ `ลบไม่ได้ คงเหลือจะไม่พอ`
3. ลดปริมาณรอบหนึ่งจนคงเหลือจะติดลบ → แก้ไม่ได้
4. ลบรอบที่ยังไม่กระทบของที่ขายไปแล้วได้ คงเหลือและค่าเฉลี่ยตรงชุดที่เหลือ
5. เงินที่จ่าย > ราคาเต็มตอนแก้ในแถว บันทึกไม่ได้
