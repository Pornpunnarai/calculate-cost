# Purchase-first warehouse — Design Spec

Date: 2026-09-09  
Status: Approved for user review  
Version: v1

แทนที่ลำดับเดิมที่สร้างวัตถุดิบก่อนแล้วค่อยซื้อเข้า และรวมกฎทับแพ็กรอบล่าสุดจาก `2026-09-09-purchase-sync-pack-design.md`

## Problem

ของในคลังไม่ควรมีได้ถ้ายังไม่ซื้อ ตอนนี้หน้าวัตถุดิบสร้างรายการได้เอง ทำให้แพ็กตั้งต้นกับของที่ซื้อจริงแยกกัน

## Goals

- มีวัตถุดิบในคลังได้ก็ต่อเมื่อซื้อเข้าสำเร็จแล้ว
- ของใหม่กรอกที่หน้าซื้อเข้า: ชื่อ, หน่วย, ปริมาณ, วันที่ซื้อ, ราคาเต็ม, เงินที่จ่าย, แหล่งซื้อ
- ของที่มีในคลังแล้วเลือกชื่อจากคลัง แล้วกรอกปริมาณ, วันที่ซื้อ, ราคาเต็ม, เงินที่จ่าย, แหล่งซื้อ
- ส่วนลดแสดงอัตโนมัติ = ราคาเต็ม − เงินที่จ่าย
- ต้นทุนต่อหน่วยใช้เงินที่จ่าย ÷ ปริมาณ ของแต่ละรอบ แล้วเฉลี่ยทุกครั้งที่ซื้อเท่าๆ กัน
- หน้าวัตถุดิบเป็นคลังดูอย่างเดียว
- แหล่งซื้อแยกจากช่องทางขาย

## Non-goals

- ไม่แก้หรือยกเลิกรายการซื้อย้อนหลัง
- ไม่เพิ่ม แก้ หรือลบวัตถุดิบจากหน้าคลัง
- ไม่มีหน้าจัดการแหล่งซื้อแยก
- ไม่รวมแหล่งซื้อกับช่องทางขาย
- ไม่เปลี่ยนสูตรเฉลี่ยต้นทุน
- ไม่เปลี่ยนหน้าขายออกนอกจากการใช้คลังเดิม
- ไม่ย้อนสร้างประวัติซื้อให้ของที่สร้างแบบเก่า

## Relation to previous specs

- `2026-09-08-menu-cost-calculator-design.md`: หน้าเมนู หน่วย ช่องทางขายยังใช้คิดต้นทุนและ GP
- `2026-09-09-buy-sell-design.md`: ขายออก ตัดคงเหลือ ของไม่พอ และค่าเฉลี่ยรอบซื้อยังใช้ หน้าซื้อเข้าและหน้าวัตถุดิบเปลี่ยนตามสเปกนี้
- `2026-09-09-purchase-sync-pack-design.md`: ถูกดูดเข้ามา แพ็กในตารางวัตถุดิบยังถูกทับเป็นปริมาณและเงินที่จ่ายของรอบล่าสุด แต่หน้าคลังไม่โชว์แพ็ก

ของที่สร้างไว้ก่อนหน้านี้ยังอยู่ในคลัง ซื้อรอบถัดไปเลือกชื่อเดิมได้ ถ้ายังไม่เคยซื้อ ต้นทุนเมนูใช้แพ็กเดิม

## Flow

1. ผู้ใช้เปิดซื้อเข้า เลือกโหมดของใหม่หรือของในคลัง
2. ของใหม่: สร้างแถววัตถุดิบ + ประวัติซื้อ + บวกคงเหลือใน transaction เดียว
3. ของในคลัง: เติมคงเหลือ + ประวัติซื้อ ทับแพ็กเป็นรอบนี้
4. เปิดหน้าวัตถุดิบเห็นชื่อ หน่วย คงเหลือ ต้นทุนต่อหน่วย (ถ้าเปิดค้างไว้ต้องรีเฟรช)
5. เมนูเลือกวัตถุดิบจากคลังได้ ขายออกตัดคงเหลือ ไม่แก้ประวัติซื้อและไม่แก้แหล่งซื้อ

## Data model

### `purchase_sources`

| Column | Type | Rules |
|---|---|---|
| id | uuid pk | |
| name | text | unique, not empty |
| is_builtin | boolean | default false |
| created_at | timestamptz | default now() |

แถวเริ่มต้น (`is_builtin = true`): Makro, ตลาด, Shopee, TikTok

ถ้าผู้ใช้พิมพ์ชื่อที่ยังไม่มี ให้ insert แล้วใช้ id นั้น ชื่อเทียบแบบ trim แล้วตรงทั้งชื่อ (ไม่แปลงตัวพิมพ์)

ไม่มีหน้าตั้งค่าแหล่งซื้อ รายการเพิ่มได้เฉพาะตอนซื้อเข้า

### `stock_purchases` (เพิ่มคอลัมน์)

| Column | Type | Rules |
|---|---|---|
| purchased_at | date | วันที่ซื้อที่ผู้ใช้กรอก แถวใหม่ต้องมี |
| list_price | numeric | ราคาเต็ม, แถวใหม่ > 0 และ `>= amount_paid` |
| purchase_source_id | uuid fk → purchase_sources.id | restrict on delete แถวใหม่ต้องมี |

`amount_paid` ยังเป็นเงินที่จ่ายจริง > 0  
ส่วนลดไม่เก็บ คำนวณตอนอ่าน: `list_price - amount_paid`

`created_at` ยังเป็นเวลาที่บันทึก ไม่ใช่วันที่ซื้อ

แถวเก่าที่ยังไม่มีค่าใหม่: วันที่โชว์จาก `created_at` ส่วนลดเป็น 0 แหล่งซื้อเป็น — ไม่เดาว่าร้านไหน คอลัมน์ใหม่เป็น nullable เพื่อไม่ย้อนแก้ประวัติ

### `ingredients`

ไม่เพิ่มคอลัมน์ ตอนซื้อเข้ายังเซ็ต

- `remaining_quantity` += ปริมาณ
- `purchase_quantity` = ปริมาณรอบนี้
- `purchase_price` = เงินที่จ่ายรอบนี้ (ไม่ใช้ราคาเต็ม)

ของใหม่: insert วัตถุดิบก่อน แล้วใส่ประวัติซื้อ คงเหลือเริ่มต้นเท่าปริมาณรอบแรก

## Atomic RPC

ขยาย `record_stock_purchase` ในไฟล์ migration ใหม่ (`create or replace`) ห้ามแก้ไฟล์ SQL ที่รันไปแล้ว

รับอย่างน้อย: โหมดของใหม่หรือของเดิม, ปริมาณ, เงินที่จ่าย, ราคาเต็ม, วันที่ซื้อ, แหล่งซื้อ, และถ้าของใหม่: ชื่อกับหน่วย

ตรวจในฟังก์ชัน: ปริมาณ ราคาเต็ม เงินที่จ่าย > 0 และเงินที่จ่าย ≤ ราคาเต็ม

ของใหม่กับประวัติต้องจบใน transaction เดียว ห้ามให้ client insert วัตถุดิบแล้วค่อยเรียกซื้อแยก

## Calculation

ปัดครึ่งขึ้น 2 ตำแหน่งตอนแสดงเท่านั้น

ส่วนลดที่โชว์ = `list_price - amount_paid`

ต้นทุนต่อหน่วยรอบ `i` = `amount_paid_i / quantity_i`

ถ้ามีประวัติ `n >= 1`: เฉลี่ย `(u1 + … + un) / n` น้ำหนักเท่ากันทุกครั้ง ไม่สนคงเหลือและยอดขาย

ถ้า `n = 0` (ของเก่าที่ยังไม่ซื้อ): `purchase_price / purchase_quantity`

ตัวอย่าง (เงินที่จ่ายตามเดิม):

| รอบ | ปริมาณ | เงินที่จ่าย | แพ็กภายใน | คงเหลือ | ต้นทุนเฉลี่ย |
|---|---|---|---|---|---|
| 1 | 100 g | 400 | 100 g / 400 | 100 | 4.00 |
| 2 | 100 g | 450 | 100 g / 450 | 200 | 4.25 |
| 3 | 50 g | 300 | 50 g / 300 | 250 | 4.83 |

ถ้ารอบ 2 ราคาเต็ม 500 จ่าย 450 ส่วนลดที่โชว์คือ 50 ไม่กระทบค่าเฉลี่ย

## UI

ภาษาไทย สกุลเงินบาท

### ซื้อเข้า `/purchases`

- สลับของใหม่ / ของในคลัง
- ของใหม่: ชื่อ, หน่วย (จากหน้าหน่วย), ปริมาณ, วันที่ซื้อ, ราคาเต็ม, เงินที่จ่าย, ส่วนลดอ่านอย่างเดียว, แหล่งซื้อ (select รายการที่มี หรือพิมพ์ชื่อใหม่)
- ของในคลัง: เลือกวัตถุดิบ, ปริมาณ, วันที่ซื้อ, ราคาเต็ม, เงินที่จ่าย, ส่วนลดอ่านอย่างเดียว, แหล่งซื้อ
- ตารางประวัติ: วันที่ซื้อ, วัตถุดิบ, แหล่งซื้อ, ปริมาณ, ราคาเต็ม, เงินที่จ่าย, ส่วนลด, คงเหลือหลังซื้อ, ต้นทุนเฉลี่ยหลังซื้อ
- อยู่หน้านี้หลังบันทึก ไม่พาไปคลัง

### วัตถุดิบ `/ingredients`

ตารางอย่างเดียว: ชื่อ, หน่วย, คงเหลือ, ต้นทุนต่อหน่วย  
ไม่มีฟอร์มเพิ่ม ไม่มีปุ่มแก้ ไม่มีปุ่มลบ ไม่โชว์แพ็ก

ถ้าโหลดประวัติซื้อไม่ได้: โชว์ว่าใช้แพ็กตั้งต้น และยังไม่มีปุ่มเพิ่มของ

### เมนู หน่วย ช่องทางขาย ขายออก

โครงเดิม ช่องทางขายยังเป็น Grab / หน้าร้าน สำหรับขาย ไม่โชว์ในฟอร์มซื้อเข้า

## Error handling

| กรณี | พฤติกรรม |
|---|---|
| ของใหม่ไม่มีชื่อหรือหน่วย | ฟอร์มไม่ผ่าน |
| ปริมาณ / ราคาเต็ม / เงินที่จ่าย ≤ 0 | ฟอร์มไม่ผ่าน |
| เงินที่จ่าย > ราคาเต็ม | ฟอร์มไม่ผ่าน |
| ไม่มีวันที่ซื้อ หรือไม่มีแหล่งซื้อ | ฟอร์มไม่ผ่าน |
| ของในคลังแต่ไม่ได้เลือกวัตถุดิบ | ฟอร์มไม่ผ่าน |
| RPC หรือเครือข่ายล้ม | บันทึกไม่สำเร็จ ไม่โชว์ว่าสำเร็จ ไม่ค้างวัตถุดิบใหม่โดยไม่มีประวัติซื้อ |

## Testing

1. ซื้อของใหม่ 100 g จ่าย 400 ราคาเต็ม 400 → คลังมีแถว คงเหลือ 100 ส่วนลด 0 ต้นทุน 4.00
2. ซื้อของเดิม 100 g จ่าย 450 ราคาเต็ม 500 → ส่วนลด 50 คงเหลือ 200 ต้นทุนเฉลี่ย 4.25 แพ็กภายใน 100/450
3. ซื้อต่อ 50 g จ่าย 300 → คงเหลือ 250 เฉลี่ย 4.83
4. พิมพ์แหล่งซื้อใหม่ แล้วรอบถัดไปต้องเลือกชื่อนั้นได้
5. จ่ายมากกว่า ราคาเต็ม บันทึกไม่ได้
6. หน้าคลังไม่มีฟอร์มเพิ่ม/แก้/ลบ
