# Menu Cost Calculator — Design Spec

Date: 2026-09-08  
Status: Draft for user review  
Version: v1

## Problem

ร้านต้องการรู้ต้นทุนแต่ละเมนูก่อนตั้งราคาขาย วัตถุดิบซื้อมาเป็นแพ็ก (เช่น Matcha 100 g ราคา 350 บาท) แต่เมนูใช้เพียงบางส่วน (เช่น 3 g) ต้องมีคลังวัตถุดิบกลางให้ทุกเมนูเลือกใช้ และต้องเห็นกำไรสุทธิหลังหัก GP ของแต่ละช่องทางขาย เช่น Shopee และไลน์แมน

ผู้ใช้ต้องการเปิดดูต้นทุนได้ตลอด ข้อมูลต้องไม่หายตอนปิดเครื่อง

## Goals (v1)

- เพิ่มหน่วยวัดเองได้ นอกจาก `g`, `ml`, `ชิ้น` (เช่น อัน, ใบ, แก้ว)
- เพิ่มวัตถุดิบเป็นข้อมูลหลัก: บันทึกตามแพ็กที่ซื้อ (ปริมาณ + หน่วย + ราคา)
- สร้างเมนูได้เมื่อมีวัตถุดิบแล้วเท่านั้น โดยเลือกจากคลังวัตถุดิบแล้วใส่ปริมาณที่ใช้
- โชว์ต้นทุนเมนูก่อน แล้วค่อยให้ใส่ราคาขาย
- เพิ่มช่องทางขายเองได้ (ชื่อ + GP%) แล้วโชว์กำไรสุทธิรายช่องทาง
- ข้อมูลอยู่บน Supabase เปิดใช้ผ่านเว็บบนอินเทอร์เน็ตได้จากมือถือหรือคอม
- UI เป็นภาษาไทย สกุลเงินบาท

## Non-goals (v1)

- ไม่มีระบบ login / สิทธิ์ผู้ใช้ (จะใช้ Supabase Auth ในเฟสถัดไป)
- ไม่มีหมวดหมู่วัตถุดิบหรือหมวดหมู่เมนู
- ไม่แปลงหน่วย (ไม่ทำ g ↔ kg, ml ↔ แก้ว)
- ไม่มีสต็อกคงเหลือ / ตัดสต็อก
- ไม่มีรายงานสรรพากร รายรับ-รายจ่าย ประวัติซื้อจากผู้ขาย
- ไม่มีระบบสั่งซื้อหรือพิมพ์ฉลากพัสดุ
- ไม่เก็บตัวเลขต้นทุนสำเร็จรูปในฐานข้อมูล

## Future (ไม่ทำใน v1 แต่ห้ามปิดทาง)

| เฟส | ขอบเขต |
|---|---|
| v2 | login, ผูกวัตถุดิบกับผู้ขาย, ประวัติการซื้อ |
| v3 | รายงานรายรับ-รายจ่าย สำหรับยื่นสรรพากร |
| v4 | สั่งซื้อ + พิมพ์ฉลากกับปริ้นเตอร์พัสดุ |

v1 เก็บแค่ **ต้นทุนปัจจุบันจากแพ็กล่าสุด** ของวัตถุดิบ ไม่สร้างตารางประวัติซื้อตอนนี้ พอมีประวัติซื้อทีหลังให้ต่อตารางใหม่แล้วอัปเดตต้นทุนปัจจุบันได้ โดยไม่ต้องรื้อสูตรเมนู

## Users

เจ้าของร้านคนเดียวใช้ก่อน (ยังไม่แยกบัญชีผู้ใช้) เปิดเว็บแล้วจัดการหน่วย วัตถุดิบ เมนู และช่องทางขาย

## Tech stack

- Next.js (App Router) + TypeScript
- Supabase (Postgres) เป็นฐานข้อมูล ไม่มีเซิร์ฟเวอร์แยกของโปรเจกต์นี้
- ขึ้นเว็บบน Netlify ให้เปิดจากที่ไหนก็ได้ (ใช้ Netlify Next.js runtime)
- ตัวแปรสภาพแวดล้อม: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- โปรเจกต์ Supabase ยังไม่มี จะสร้างตอน implement พร้อม SQL ของตารางด้านล่าง

## Architecture

หน้าเว็บคุยกับ Supabase โดยตรงผ่าน client SDK ตรรกะคิดเงินอยู่ฝั่งแอป (pure functions ที่ทดสอบได้อิสระ) ไม่มี backend ของเราเองใน v1

โมดูลที่แยกกัน:

1. **units** — หน่วยวัด
2. **ingredients** — คลังวัตถุดิบ (ข้อมูลหลัก)
3. **products** — เมนู + สูตร (เลือกจากคลัง)
4. **sales_channels** — ช่องทางขาย + GP%
5. **costing** — คำนวณต้นทุนและกำไรจากข้อมูลด้านบน ไม่มีตารางเก็บผลลัพธ์

ลำดับการใช้งานที่บังคับ:

1. หน่วยระบบมีมาให้แล้ว (`g`, `ml`, `ชิ้น`) เพิ่มหน่วยอื่นได้ตามต้องการ
2. เพิ่มวัตถุดิบทั้งหมดก่อน (เช่น 10 รายการ)
3. จึงสร้างเมนู โดยเลือกวัตถุดิบจากคลังแล้วใส่ปริมาณ
4. เห็นต้นทุนรวมก่อน แล้วค่อยใส่ราคาขาย
5. ช่องทางขายเพิ่มเมื่อไหร่ก็ได้ ตารางกำไรขึ้นเมื่อมีราคาขายและมีช่องทางแล้ว

## Data model

ชื่อตารางและคอลัมน์ใช้ภาษาอังกฤษในฐานข้อมูล

### `units`

| Column | Type | Rules |
|---|---|---|
| id | uuid pk | gen_random_uuid() |
| name | text | required |
| symbol | text | required, unique |
| is_builtin | boolean | default false; `g`, `ml`, `ชิ้น` เป็น true |
| created_at | timestamptz | default now() |

Seed: กรัม/`g`, มิลลิลิตร/`ml`, ชิ้น/`ชิ้น` และ `is_builtin = true`

ลบหน่วย builtin ไม่ได้ ลบหน่วยที่วัตถุดิบยังอ้างถึงไม่ได้

### `ingredients`

| Column | Type | Rules |
|---|---|---|
| id | uuid pk | |
| name | text | required; ชื่อซ้ำได้ (Matcha A / Matcha B เป็นคนละแถว) |
| purchase_quantity | numeric | > 0 |
| purchase_unit_id | uuid fk → units.id | required |
| purchase_price | numeric | > 0 |
| created_at | timestamptz | |
| updated_at | timestamptz | |

ต้นทุนต่อหน่วย **ไม่เก็บในตาราง** คำนวณตอนอ่าน: `purchase_price / purchase_quantity`

ลบวัตถุดิบที่ยังถูกเมนูใช้อยู่ไม่ได้

แก้ `purchase_unit_id` ได้เฉพาะตอนที่ยังไม่มีเมนูใช้วัตถุดิบนั้น ถ้ามีเมนูใช้แล้วแก้ได้แค่ชื่อ ปริมาณซื้อ และราคาแพ็ก ไม่แก้หน่วย เพื่อไม่ให้สูตรที่ผูกหน่วยเดิมเพี้ยน

### `products`

| Column | Type | Rules |
|---|---|---|
| id | uuid pk | |
| name | text | required |
| selling_price | numeric | nullable, ถ้ามีค่าต้อง > 0 |
| created_at | timestamptz | |
| updated_at | timestamptz | |

สร้างเมนูได้เมื่อมีวัตถุดิบอย่างน้อย 1 รายการในระบบ อนุญาตให้เซฟโดยยังไม่มีสูตรและยังไม่มีราคาขาย

### `product_ingredients`

| Column | Type | Rules |
|---|---|---|
| id | uuid pk | |
| product_id | uuid fk → products.id | on delete cascade |
| ingredient_id | uuid fk → ingredients.id | restrict on delete |
| quantity | numeric | > 0 |

Unique `(product_id, ingredient_id)` — วัตถุดิบชนิดเดียวกันในเมนูเดียวมีได้บรรทัดเดียว หน้าฟอร์มไม่ให้เลือกของซ้ำในเมนูเดียวกัน ถ้าต้องการใช้มากขึ้นให้แก้ปริมาณบนบรรทัดเดิม

หน่วยของปริมาณในสูตรคือหน่วยเดียวกับ `ingredients.purchase_unit_id` ไม่มีคอลัมน์หน่วยแยกในสูตร และไม่มีการแปลงหน่วย

### `sales_channels`

| Column | Type | Rules |
|---|---|---|
| id | uuid pk | |
| name | text | required, unique |
| fee_percent | numeric | 0 ถึง 100 inclusive; ค่า 12 แปลว่า 12% ไม่ใช่ 0.12 |
| created_at | timestamptz | |

ช่องทางเป็นของร้านทั้งร้าน ไม่ผูกต่อเมนู ทุกเมนูที่ใช้ราคาขายจะคำนวณกำไรเทียบทุกช่องทางที่มี

### ความสัมพันธ์ (สรุป)

```
units 1 ──< ingredients
ingredients 1 ──< product_ingredients >── 1 products
sales_channels (อิสระ ใช้ตอนคำนวณกำไร)
```

ไม่มี `user_id` ใน v1 ทั้งโปรเจกต์เป็นร้านเดียว ตอนมี login จะเพิ่มคอลัมน์หรือตาราง workspace โดยไม่ต้องรื้อสูตรเมนู

## Calculation

คำนวณภายในด้วยความละเอียดเต็มของตัวเลข รวมทุกบรรทัดก่อน แล้วปัดครึ่งขึ้น (round half up) เป็นทศนิยม 2 ตำแหน่งตอนแสดงผลเท่านั้น ไม่ปัดทีละบรรทัดแล้วนำมาบวก เพราะจะทำให้ผลรวมเพี้ยน

ให้

- `unit_cost(ingredient) = purchase_price / purchase_quantity`
- `line_cost = unit_cost(ingredient) * product_ingredient.quantity`
- `product_cost = sum(line_cost)` ของทุกบรรทัดในสูตร

ถ้ายังไม่มีบรรทัดสูตร `product_cost = 0`

เมื่อมี `selling_price`:

- `channel_fee = selling_price * (fee_percent / 100)`
- `net_received = selling_price - channel_fee`
- `net_profit = net_received - product_cost`

ถ้ายังไม่มี `selling_price` ไม่คำนวณค่า GP / กำไร (ไม่โชว์ตารางกำไร)

### ตัวอย่างที่ใช้ตรวจความถูกต้อง

วัตถุดิบ: Matcha A ซื้อ 100 g ราคา 350 บาท → ต้นทุนต่อหน่วย 3.50 บาท/g  
สูตรใช้ 3 g → ต้นทุนบรรทัดนี้ 10.50 บาท

เมนูต้นทุนรวม 25.00 บาท ราคาขาย 80.00 บาท ช่องทาง Shopee GP 12%:

- ค่า GP = 9.60
- ได้เงินจริง = 70.40
- กำไรสุทธิ = 45.40

เปลี่ยนราคาแพ็กวัตถุดิบแล้วต้นทุนทุกเมนูที่ใช้อัปเดตตาม เพราะคำนวณใหม่ทุกครั้งที่อ่าน ไม่ได้เก็บผลลัพธ์ไว้

## UI

ภาษาไทยทั้งแอป จัดหน้าเป็น 4 ส่วนใน navigation:

1. วัตถุดิบ (จุดเริ่มต้นหลัก)
2. เมนู
3. หน่วย
4. ช่องทางขาย

### วัตถุดิบ

- รายการ: ชื่อ, แพ็กที่ซื้อ (ปริมาณ + หน่วย + ราคา), ต้นทุนต่อหน่วยที่คำนวณแล้ว
- ฟอร์มเพิ่ม/แก้: ชื่อ, ปริมาณที่ซื้อ, หน่วย (เลือกจาก `units`), ราคาแพ็ก
- ลบได้เมื่อไม่มีเมนูอ้างถึง

### เมนู

- ถ้ายังไม่มีวัตถุดิบในระบบ: ห้ามสร้างเมนู โชว์ข้อความและปุ่มไปหน้าวัตถุดิบ
- รายการเมนูโชว์ชื่อ + ต้นทุนเป็นหลัก ราคาขาย/กำไรเป็นรอง ถ้ายังไม่ตั้งราคาขาย แสดงว่ายังไม่ตั้งราคา
- หน้าเพิ่ม/แก้เรียงตามลำดับนี้เท่านั้น:
  1. ชื่อเมนู
  2. เลือกวัตถุดิบจากคลัง + ปริมาณที่ใช้ เพิ่มได้หลายบรรทัด (ของชิ้นเดียวกันใช้ซ้ำได้หลายเมนู)
  3. โชว์ต้นทุนรวมให้อ่านเด่นทันที พร้อมแยกต้นทุนรายวัตถุดิบ แม้ยังไม่มีราคาขาย
  4. ช่อง «อยากขายเท่าไหร่»
  5. เมื่อมีราคาขายและมีช่องทางขาย จึงโชว์ตารางต่อช่องทาง: ค่า GP, ได้เงินจริง, กำไรสุทธิ
- เซฟได้แม้ยังไม่มีสูตรหรือยังไม่มีราคาขาย

### หน่วย

- รายการหน่วย เพิ่มชื่อ + สัญลักษณ์ได้
- builtin ลบไม่ได้

### ช่องทางขาย

- เพิ่มชื่อ + GP%
- ถ้ายังไม่มีช่องทาง หน้าเมนูยังโชว์ต้นทุนและราคาขายได้ แต่ยังไม่มีตารางกำไร

## Error handling

| กรณี | พฤติกรรม |
|---|---|
| ปริมาณซื้อ / ราคาแพ็ก / ปริมาณสูตร ≤ 0 | ฟอร์มไม่ผ่าน ไม่บันทึก |
| GP% นอกช่วง 0–100 | ฟอร์มไม่ผ่าน |
| ราคาขาย ถูกใส่แต่ ≤ 0 | ฟอร์มไม่ผ่าน; ว่าง = ยังไม่ตั้งราคา บันทึกได้ |
| ลบหน่วย builtin | ห้าม |
| ลบหน่วยที่วัตถุดิบใช้อยู่ | ห้าม พร้อมข้อความให้แก้วัตถุดิบก่อน |
| ลบวัตถุดิบที่เมนูใช้อยู่ | ห้าม พร้อมข้อความให้เอาออกจากสูตรก่อน |
| เลือกวัตถุดิบซ้ำในเมนูเดียวกัน | ฟอร์มกันไว้ unique constraint เป็นตาข่ายชั้นที่สอง |
| Supabase ล่ม / เน็ตขาด | บอกว่าบันทึกหรือโหลดไม่สำเร็จ ไม่แสดงว่าสำเร็จ |
| ยังไม่มีวัตถุดิบ | หน้าเมนูไม่ให้สร้าง |

## Security (v1)

ยังไม่มี login ตารางเปิดให้อ่าน/เขียนด้วย anon key ของโปรเจกต์นี้ได้ (ร้านเดียวใช้) ใครมี URL เว็บและ key ในตัวแอปจะเข้าถึงข้อมูลได้

ตอนมี login: เปิด Supabase Auth + RLS จำกัดรายผู้ใช้/ร้าน โดยไม่ต้องรื้อตารางสูตรเมนู

ห้าม commit ไฟล์ `.env.local` ที่มี URL/key จริง

## Testing

ทดสอบฟังก์ชันคิดเงินแยกจาก UI:

1. ซื้อ 100 g ราคา 350 ใช้ 3 g → บรรทัดต้นทุน 10.50
2. รวมหลายวัตถุดิบได้ `product_cost` ถูกต้อง
3. ไม่มีสูตร → ต้นทุน 0
4. เปลี่ยน `purchase_price` แล้วต้นทุนเมนูเปลี่ยนตาม
5. ขาย 80 GP 12% ต้นทุน 25 → ได้เงินจริง 70.40 กำไรสุทธิ 45.40
6. ไม่มีราคาขาย → ไม่มีผลกำไร (ไม่คำนวณ)
7. GP 0% → ได้เงินจริงเท่าขาย กำไร = ขาย − ต้นทุน
8. ลบวัตถุดิบที่ถูกใช้ต้องล้มเหลว

## Deployment

- สร้างโปรเจกต์ Supabase ใหม่ รัน SQL สร้างตาราง + seed หน่วย
- Deploy แอปขึ้น Netlify (Next.js runtime) ชี้ไปที่โปรเจกต์ Supabase นั้น
- ใส่ `NEXT_PUBLIC_SUPABASE_URL` และ `NEXT_PUBLIC_SUPABASE_ANON_KEY` ใน environment variables ของ Netlify
- ผู้ใช้เปิด URL ได้ตลอด ข้อมูลอยู่บนคลาวด์ไม่หายกับเครื่องท้องถิ่น
